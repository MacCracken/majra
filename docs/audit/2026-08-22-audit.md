# P(-1) Hardening Audit — 2026-08-22 (shipped as 2.6.9)

First audit under the P(-1) process in [`CLAUDE.md`](../../CLAUDE.md). It is
also the first entry in `docs/audit/`, which the process describes as "created
when first earned".

**115 findings confirmed, 2 refuted** across 23 `src/` modules and one test
file. Every finding was produced by one reviewer and then re-checked by a
separate adversarial verifier instructed to default to *refuted* when
uncertain; several were additionally reproduced by compiling probe programs.

## Method

Six review lenses, each re-checked by an independent adversarial verifier:

| Lens | Scope |
|---|---|
| `resp-pg-wire` | `redis_backend.cyr`, `postgres_backend.cyr` — remote peer treated as hostile |
| `ws-http` | `ws.cyr`, `admin.cyr` — RFC 6455 conformance, admin trust boundary |
| `crypto` | `ipc_encrypted.cyr`, `signed_envelope.cyr`, `envelope.cyr` — nonce discipline, constant-time compares, canonicalisation |
| `concurrency` | `queue.cyr`, `pubsub.cyr`, `relay.cyr`, `barrier.cyr`, `heartbeat.cyr` — the modules a 100-worker pool drives |
| `datastructures` | `ratelimit.cyr`, `metrics.cyr`, `counter.cyr`, `dag.cyr`, `fleet.cyr`, `namespace.cyr`, `transport.cyr`, `error.cyr` |
| `syscall-fs-sql` | `ipc.cyr`, `patra_queue.cyr`, `main.cyr` — syscall returns, socket permissions, SQL construction |

Reviewers were briefed on the Cyrius semantics that generate false positives —
above all that a **global** `var buf[N]` is N x 8 bytes while a **local** one is
N bytes, which is why `redis_backend.cyr`'s `while (pos < 4088)` loop over
`var _resp_buf[512]` is in range and not the overflow it looks like.

## The two critical findings

### 1. Both directions of an encrypted IPC channel shared one nonce space

`src/ipc_encrypted.cyr`. Both endpoints share a single pre-shared key, and each
derived its nonces from its own `send_counter` starting at 0 with **nothing in
the 12-byte nonce distinguishing the two directions**. The first message each
way therefore used a byte-identical `(key, nonce)` pair, as did every later pair
at the same counter.

Under AES-GCM this is the one failure the construction cannot survive.
Identical `(key, nonce)` means an identical keystream, so XORing the two
ciphertexts yields the XOR of the two plaintexts; a nonce collision also leaks
the GHASH subkey, which lets an attacker forge valid tags for arbitrary
messages. Confidentiality *and* integrity fall together.

Fixed by making the role a required constructor argument and placing it in
nonce byte 0. This is a signature change to a public function, and it is not
optional — the old two-argument form cannot be made safe.

### 2. PostgreSQL NULL columns crashed the client

`src/postgres_backend.cyr`. `_pg_read_be32` composes four **zero-extended**
`load8` results, so it can never return a negative number: PostgreSQL's NULL
sentinel (int32 `-1`, on the wire as `FF FF FF FF`) came back as `4294967295`.
The `col_len < 0` NULL guard in `pg_query` was therefore unreachable dead code,
and a NULL column took the value branch — `fl_alloc(4294967296)` followed by a
4 GiB `memcpy` out of a DataRow body a few bytes long.

This is reachable from ordinary traffic, not a hostile server: majra's own
`pg_init_workflow_tables` declares `input_json`, `output_json`, `error`,
`started_at` and `completed_at` nullable. `tests/test_live.tcyr` never fired it
because it only ever selects non-NULL literals.

Verified empirically before fixing — a compiled probe confirmed `load8`
zero-extends and that Cyrius shift/or precedence matches C, so the guard could
not fire. Fixed with a sign-extending `_pg_read_i32`.

## Themes

**Wire lengths were trusted.** Every parser took an allocation size, a loop
bound or a pointer offset straight off the wire. The sharpest case:
`$9223372036854775807` in RESP makes `blen + 2` wrap **negative**, and
`_fl_class` routes a negative size down the `size <= 16` path — so `fl_alloc`
returned a 16-byte block that `str_new` then labelled `INT64_MAX` long.

**Parameters were accepted and ignored.** `redis_connect` and `pg_connect` both
took a `host` and dialled `INADDR_LOOPBACK()` regardless. `majra_admin_serve`
documented "bind 127.0.0.1 for localhost-only" while passing a `char*` where
`sockaddr_in` wants a packed integer — for an endpoint with no authentication,
that binding is the whole security boundary, and it was decided by a pointer
value. `transport_send`/`transport_recv` dropped the `len` argument their own
vtable contract documents.

**The bump allocator was on hot paths.** `map_keys` builds a vec from
`default_alloc()`, which never reclaims. It ran on every `pubsub_publish`, every
`fleet_submit`, every relay receive, and every dedup eviction pass. Removing it
is also where this release's performance wins came from.

**Documentation described code that does not exist.** `dag.cyr` claimed
`thread_create`/`join` parallel execution within tiers and calls neither;
`ws.cyr` described a pub/sub bridge with no serve loop; `admin.cyr` documented
`/ratelimit/:key` while returning global counters for any key.

## External research (step 4)

| Surface | Finding |
|---|---|
| WebSocket | CVE-2026-54466 (websocket-driver) and CVE-2026-1528 (undici) are both wire-length integer overflow / unbounded allocation. majra's variant was different and arguably worse: the 127 / 64-bit length form was **never implemented**, so the sentinel was used as a literal length and the eight length bytes were consumed as payload — a peer-controlled frame desync. |
| AES-GCM | NIST SP 800-38D Rev.1 (draft 2025-01-06, publication 2026-06-01) removes tags below 96 bits and clarifies IV construction. majra uses 128-bit tags. The nonce-construction guidance is what surfaced finding 1. |
| Ed25519 | CVE-2026-33895 (Forge) is a forgery from a missing `S < L` check (RFC 8032 5.1.7); implementations also diverge on small-order point rejection and the cofactored verification equation. majra delegates verification to sigil, so strictness is sigil's property — recorded in the threat model rather than reimplemented. |
| RESP | Redis caps bulk strings at 512 MB via `proto-max-bulk-len`; a hostile server returning a nonsensical length causes unbounded **client-side** allocation. majra applied no cap at all. |

## Refuted (2)

Both were factually accurate observations that did not survive as defects:

- **`signed_at` is not covered by the signature.** True, but majra has no
  serializer or deserializer for a `SignedEnvelope` — the field is written once
  from the local clock and never crosses a trust boundary. The proposed
  mitigation was also wrong: `envelope_timestamp` is `CLOCK_MONOTONIC` and
  meaningless across nodes. Resolved as a comment.
- **`TRIGGER_ANY` is not honoured by tier construction.** True, but nothing
  documents `TRIGGER_ANY` as "run as soon as any dependency completes"; it *is*
  honoured where it is defined, in the skip check. An inferred feature
  expectation, not a defect.

## Not fixed in 2.6.9

Deliberate, each with the reasoning recorded at the call site:

- **pubsub's blocking fan-out.** An abandoned subscriber wedges publishes to
  its topic permanently. But blocking is a backpressure contract 2.5.3
  established and `test_pubsub_no_head_of_line_block` asserts, and 2.5.3 already
  bounded the blast radius to the single publish call. Switching to
  `chan_try_send` would trade a wedge for silent message loss — the worse
  failure for a queue engine. Needs unsubscribe plus a lag policy.
- **PostgreSQL cleartext auth and no TLS.** Implementing SCRAM-SHA-256 and
  `SSLRequest` is a feature, not a repair. The connect now fails closed on auth
  type 10 rather than downgrading, and the limitation is documented at the top
  of the module.
- **Per-key ratelimit stats.** `/ratelimit` returns global counters; the
  response now says `"scope":"global"` so it is at least self-describing.
- **Parallel DAG tier execution.** Header corrected to match the code.

## Performance

Measured head-to-head against a `dda5b72` (2.6.8) build of the same
`benches/bench_all.bcyr`, three trials each, rather than against a stored row:

| Target | 2.6.8 | 2.6.9 | Delta |
|---|---|---|---|
| `pubsub_publish_nosub` | ~299ns | 193ns | **-35%** |
| `fleet_stats_100` | ~11.6us | ~9.6us | **-16%** |
| `circuit_state` | 3ns | 3ns | unchanged |
| `ratelimit_check` | 1.698us | 1.699us | unchanged |
| `pq_enqueue` | ~572ns | ~617ns | **+7.9%** |

The two wins are the `map_keys` bump-allocation removals. `pq_enqueue` is a
consistent regression, below the 10% flag threshold; the priority-queue code
itself was not modified, so this is most likely code-layout / i-cache movement
from the larger binary rather than added work on that path.

`circuit_state` initially regressed 2ns -> 49ns from the mutex added for the
half-open probe gate. Since that check runs per request, a lock-free fast path
was added for the common below-threshold case (a stale read there costs at most
a one-request delay in tripping, and `circuit_record_failure` re-reads under the
lock), restoring it to 3ns.

## Test surface

410 -> 515 assertions. New coverage is concentrated on the defects themselves:
the int32 sign boundary and NULL sentinel, IPv4 parsing and rejection, RESP
wraparound arithmetic, role-separated nonces, rekey refusal, base64 validation,
an `src/ipc.cyr` socketpair round-trip (that module shipped in all four dist
profiles with **no test in any suite**, which is why its defects went
unnoticed), SQL-injection payloads stored verbatim, the concurrency cap, cancel
semantics, job-map release, fleet re-registration, and namespace prefix
validation.

it was codifying the unbounded-growth leak. It now asserts the tracking map
drains to 0.
